# 项目经历：AI 评测平台（AI Evaluation Platform）

## 一句话简介

一个面向 RAG、AI Agent、多轮对话等 LLM 应用场景的**自托管 AI 应用评测工作台**，把数据集构建、场景化指标、LLM-as-a-Judge 自动评分、被测接口实时评测、评测报告、人工复核与 A/B 盲测整合为端到端的 Web 工作流。

## 真实业务场景

面向 AI 应用（RAG 知识库问答、任务型/客服 Agent、多轮对话机器人）在**模型、Prompt、检索链路或 Agent 实现迭代与上线前**的质量评估与选型对比：团队用它把"要不要换模型/换检索策略/换 Agent 实现"这类决策，从主观感觉变成有逐条评分理由、有报告对比、有人工盲测佐证的可追溯证据。

## 技术栈

- 前端：React 18 + TypeScript + Ant Design 5 + Vite
- 后端：FastAPI + SQLAlchemy + Pydantic + SQLite（可通过 `DATABASE_URL` 切换 PostgreSQL）
- AI/评测：OpenAI 兼容 LLM（默认 DashScope Qwen Plus）+ 自研 LLM-as-a-Judge 评测执行器
- 基础设施：asyncio + httpx 异步调用、PyMuPDF/Tesseract 文档解析

## 工作内容亮点（11 项，STAR）

### 1. 从 0 到 1 搭建评测闭环平台

- **S（背景）**：团队的大模型评测散落为一次性脚本，指标口径、样本和结论无法沉淀与复用。
- **T（任务）**：把评测做成平台化工程流程，而不是临时脚本。
- **A（行动）**：以 FastAPI + React 分层架构，将 数据 → 场景 → 指标 → Judge 模型 → 执行 → 报告 → 人工复核 → 盲测 全链路产品化，场景配置以快照冻结保证历史任务可复现。
- **R（结果）**：落地 13 个前端页面组件 / 12 条前端路由、62 个 REST API（9 个路由模块）；评测样本与场景配置可沉淀复用，取代散落脚本。

### 2. 自研原生 LLM-as-a-Judge 评测引擎

- **S（背景）**：直接依赖第三方指标库时，评判规则与业务口径耦合、难以定制和解释。
- **T（任务）**：做可控、可解释、可配置的自有评测执行器。
- **A（行动）**：自研统一指标执行层，区分「LLM 语义指标 / 确定性检索指标 / 确定性 Agent 指标 / 用户自定义 Prompt 指标（numeric、discrete、aspect_critic 三种模式）」；统一约束 Judge 只依据样本字段评分、禁止引入外部知识，强制返回严格 JSON `{score, reason}`，并对 JSON 模式失败做无 `response_format` 降级重试。
- **R（结果）**：沉淀 22 个内置指标定义；每条样本每个指标均持久化 score 与 ≤800 字评分理由，实现逐条可解释、可追溯。

### 3. 场景化指标体系与阈值/权重配置

- **S（背景）**：RAG、Agent、多轮对话的评判标准完全不同，不能用一套指标打天下。
- **T（任务）**：让不同应用类型各自可配指标、权重、通过阈值与 Prompt 覆盖。
- **A（行动）**：预置 RAG/Agent/多轮对话 3 套场景模板；通过 `ScenarioMetric` 支持逐指标 `weight` 与 `pass_threshold`，并允许场景级 `prompt_override` 覆盖业务评判规则；汇总统计按指标输出 mean / min / max / pass_rate / error_count。
- **R（结果）**：3 个预置场景模板覆盖 22 个内置指标；每轮评测输出逐指标通过率与均值，支持按阈值判定整条样本是否通过。

### 4. RAG 评测数据集自动构建（文档 → 问答样本）

- **S（背景）**：RAG 评测缺少带标准答案的测试集，人工造题成本高。
- **T（任务）**：从知识库文档自动产出可评测、可回溯的问答样本。
- **A（行动）**：实现版面感知 PDF 解析与噪声治理（页眉页脚/页码、修订记录、表单回执、OCR 乱码识别过滤）+ 结构化/长度双模式分块（默认 900 字、重叠 120），对每个分片做质量打分并据此分配出题数量；调用 LLM 生成问题与标准答案，再做二次校验与去重（剔除"文档提到了什么"类元问题）。
- **R（结果）**：支持 txt/md/csv/json/docx/pdf 7 类格式，扫描件走 PyMuPDF + Tesseract（chi_sim+eng）OCR；产出携带 `reference_context_ids` 标准证据分片的样本，直接支撑 HitRate@K / MRR 检索单测。

### 5. 被测接口实时评测（打通"调用→抽取→评测→回写"）

- **S（背景）**：上线前需要直接对真实的 Chat/RAG/Agent 服务评测，而非只评已有结果。
- **T（任务）**：让平台能实时调用被测接口并自动完成评测。
- **A（行动）**：基于 httpx 支持 json / SSE 两种传输协议，请求体模板支持 `{{user_input}}` 变量渲染，响应通过字段路径映射抽取 response / retrieved_contexts / tool_calls / retrieved_context_ids；保留完整 endpoint trace（状态码、latency_ms、原始响应）；支持结果 write_back 自动回写数据集并扩展字段 Schema。
- **R（结果）**：覆盖 2 种传输协议与 4 类响应字段抽取；接口调用延迟、trace 与字段映射告警均落库，失败可逐行定位。

### 6. 人工盲测 A/B 对比

- **S（背景）**：自动指标不等于真实用户偏好，模型/接口选型缺少主观证据。
- **T（任务）**：提供人工偏好层面的对比能力。
- **A（行动）**：支持 LLM vs LLM、Endpoint vs Endpoint、LLM vs Endpoint 三类对比；用 MD5 哈希对每一行随机化 A/B 展示顺序以消除位置偏见；生成答案并发执行并汇总投票（model_a_wins / model_b_wins / ties / both_bad / 未答样本）。
- **R（结果）**：3 种对比组合、异步并发 3 路，输出结构与 A/B 胜率统计，与自动评测形成互补证据。

### 7. 评测报告、逐条理由与报告对比

- **S（背景）**：只有汇总分无法定位失败样本，也无法做版本回归。
- **T（任务）**：让结果可读、可复核、可对比。
- **A（行动）**：输出任务进度、通过率、逐指标摘要；报告详情逐条展示每个指标的得分、Judge 理由、是否通过、接口 trace；提供人工复核字段（状态/分数/标签/备注）；支持报告对比当前与基线（指标均值 delta、通过率 delta、失败/错误数变化、逐行差异）。
- **R（结果）**：报告列表 / 详情 / 对比三类视图；回归对比精确到 pass_rate 与 fail_count 的 delta 级别，支撑上线决策。

### 8. 多类型数据集与可扩展字段 Schema

- **S（背景）**：样本形态多样——单轮问答、多轮对话、RAG 上下文、工具调用链。
- **T（任务）**：用统一的数据模型承载异构样本。
- **A（行动）**：设计统一 Dataset / DatasetRow 契约，支持 user_input、contexts、tool_calls、reference、rubrics、业务自定义字段与 `field_schema`；提供 CSV/JSON 导入导出；接口评测回写时自动补齐 Schema 字段。
- **R（结果）**：单一数据集模型同时服务 RAG/Agent/多轮对话评测；字段可读可写回写，降低换场景的重建成本。

### 9. 异步任务编排与运行稳定性

- **S（背景）**：评测与数据集生成耗时较长，需进度可见、可取消、失败可收敛。
- **T（任务）**：保证长任务稳定执行且不影响接口响应。
- **A（行动）**：用线程 + asyncio 解耦执行，避免阻塞 FastAPI 事件循环；逐行写入进度与执行日志，支持任务取消；RAG 生成任务设 15 分钟超时并自动回收"陈旧运行中"任务为失败；盲测用信号量限制并发。
- **R（结果）**：任务级进度 0→1、逐行返回 execution_time_ms；超时任务自动标记失败并保留已完成结果，避免脏状态。

### 10. 工程化、开源与安全基线

- **S（背景）**：项目需可快速上手、可维护、可安全交付。
- **T（任务）**：保证交付质量与安全合规。
- **A（行动）**：前后端分层、Python 类型注解、Pydantic 校验；提供 `SEED_ON_STARTUP` 种子数据一键体验；编写 5 个模块的单元测试；对 API Key 与 endpoint Authorization 做响应脱敏；`.env`、数据库、上传文件、构建产物从版本控制排除；补齐中英双语 README 与使用/评测/存储/安全等文档。
- **R（结果）**：5 个测试模块，以 Apache-2.0 开源发布 v0.1.0；脱敏与 gitignore 构成基础安全基线。

### 11. RSI 自进化：评测驱动的配置自我改进闭环

- **S（背景）**：平台能"评"不能"改"——指标判据与通过阈值的好坏依赖人工经验；且判据与数据集同源调整时极易"自证"（用改过的数据证明改过的判据）。
- **T（任务）**：在既有评测内核之上构建「归因 → 提案 → 影子回归 → 验收 → 写回」的可审批、可回滚自进化闭环，且不修改评测引擎的评分逻辑与 Judge 契约。
- **A（行动）**：设计 4 表模型（`rsi_loops` / `rsi_iterations` / `rsi_proposals` / `rsi_config_versions`），版本表 append-only、仅允许写回滚标记，保证审计不可篡改；建立字段级 Patch 白名单（覆盖 4 类配置对象、8 个可改字段），限制文本长度 ≤4000、阈值单轮变化 ≤0.15，并拒绝疑似凭据（`sk-`/`Bearer`）与敏感字段（`authorization`/`api_key`/`extra_headers`）；用 MD5 稳定哈希按循环划分 train/holdout（默认 0.3），从基线快照冻结每指标参考阈值（缺省 0.7），验收只以 holdout 为口径、归因只读 train 证据，从机制上杜绝自证；归因为「规则聚类 + LLM 聚类」双层且 LLM 失败自动降级，提案与评审同模型时风险等级自动上浮一级以抑制自评偏差；写回先快照后落库并二次漂移复核（`before_value` 需同时匹配冻结快照与实时实体），默认人工审批、仅低风险补丁且 holdout ≥30 行允许自动采纳；以后台线程 + asyncio 串行驱动迭代，配置硬预算（≤3 轮 / ≤50 行每轮 / ≤300 次 LLM 调用 / ≤45 分钟 / ≤3 提案每轮），连续 2 轮无增益即收敛，重启后自动回收超预算的"运行中"循环。
- **R（结果）**：落地 4 张 RSI 数据表、17 个 REST 接口、2 条前端路由与 7 个自进化组件；6 个 RSI 测试模块共 40 个用例覆盖策略、补丁、引擎、回滚、归因与 API；验收口径含目标增益 ≥0.03、受保护指标降幅 ≤0.02、新增失败 0 条、错误率上升 ≤0.02，实现可审批、可回滚、可审计的配置自进化闭环。

## 能力专题（结合项目实际能力，STAR）

> 说明：以下仅收录本项目**真实具备**的能力方向；项目未涉及的能力（多模态大模型、多智能体、Agent Skills、MCP）不做夸大描述，见文末"未覆盖说明"。

### RAG

- **S**：RAG 应用必须同时保证检索质量与生成可信度，只评一侧不足以定位问题。
- **T**：量化检索召回/精确与生成忠实/相关/完整。
- **A**：检索侧用 Context Recall、Context Precision、Contextual Relevancy，并补充确定性指标 HitRate@K 与 MRR（基于 `reference_context_ids` 做检索单测）；生成侧用 Faithfulness、Factual Correctness、Answer Relevancy、Answer Completeness；数据集由文档自动生成并携带标准证据分片 ID。
- **R**：项目内含 8+ 个 RAG 相关内置指标，覆盖检索与生成两侧，并支持检索链路单独打分。

### Agent

- **S**：Agent 是否"用对工具、传对参数、走对步数"很难靠最终回复判断。
- **T**：评估工具调用链路的正确性与任务完成度。
- **A**：LLM 侧指标 Task Completion、Goal Accuracy 评判任务闭环；确定性指标 Tool Correctness（工具名 + 参数完全匹配）、Argument Correctness（同名工具下参数匹配度）、Step Efficiency（实际步数与期望步数偏差惩罚）——三者无需 Judge、可复现。
- **R**：项目内含 5 个 Agent 内置指标，其中 3 个为确定性指标，评分稳定可复现。

### 评测 / 评估（LLM-as-a-Judge 与人工结合）

- **S**：自动评测的可信度与上线决策需要可解释证据支撑。
- **T**：用"自动指标 + 人工复核 + 人工盲测"组合提供决策证据。
- **A**：原生 LLM-as-a-Judge 引擎输出逐条评分理由；人工复核字段（状态/分数/标签/备注）支持人工干预；A/B 盲测补充主观偏好；报告对比支持版本回归。
- **R**：22 个内置指标、每条样本逐指标持久化 score + reason，形成"自动评测→人工复核→盲测→回归对比"的完整评估闭环。

## 未覆盖说明（如实说明，避免夸大）

本项目**未涉及**以下方向，故不作为项目亮点：

- **多模态 AI**：项目仅使用扫描 PDF 的 OCR（PyMuPDF + Tesseract，chi_sim+eng）做"文档图像 → 文本"处理，属于文档解析，并非多模态大模型推理能力。
- **多智能体（Multi-Agent）**：无多 Agent 编排与协作调度。
- **Agent Skills**：无 Skill 机制或可插拔技能体系。
- **MCP（Model Context Protocol）**：未接入 MCP 协议或 MCP Server。

当前版本已知限制：暂未包含登录认证、RBAC、审计日志与敏感字段加密存储，也未引入数据库迁移工具（Alembic）。
